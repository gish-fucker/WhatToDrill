# WhatToDrill 训练现场与本地 Beta 漏斗设计

## 1. 目标与范围

本轮只修复首次训练条件、动作记录单位、休息过渡和手机训练操作，并增加不联网的本地 Beta 漏斗。不得增加社区、排行榜、视频课程、支付、新导航或首页分析卡片。

本地 Beta 漏斗是当前浏览器中的封闭测试记录，不是在线用户分析。事件不会进入云同步、完整训练备份、普通数据导入或第三方分析平台。

## 2. 首次训练条件

“居家无器械”采用真实默认选中：HTML radio 带默认 `checked`，每次打开首次训练弹窗时，若没有有效的已存首次配置，表单重置为该选项。视觉样式只依据 `:checked`，不再用第一个标签伪装选中。

表单继续要求训练经验和目标；二者保留现有真实默认值。键盘焦点进入训练条件组，方向键可切换选项，屏幕阅读器能读取 fieldset、legend、选中状态和错误。刷新后重新打开弹窗仍有且只有一个训练条件被选中，并可直接提交。

## 3. 动作记录类型

规范字段为 `recordType`，允许值：

- `weighted_reps`：重量和次数；
- `bodyweight_reps`：仅次数，不显示重量快捷键；
- `assisted_or_added_weight_reps`：次数及“辅助/加重”语义，辅助量以负值兼容保存，加重量以正值保存；
- `duration_seconds`：秒；
- `duration_minutes`：分钟；
- `completion_only`：只记录完成，不显示数字输入。

`WorkoutSessionModel` 负责规范化、旧数据推断、会话草稿迁移和正式记录物化。旧 `metric` 映射为：`seconds -> duration_seconds`、`minutes -> duration_minutes`、`completion -> completion_only`、`reps ->` 根据动作、备注和已有重量推断；无法可靠识别的旧自定义动作默认 `weighted_reps`，以保留旧版可记录重量和次数的能力。内置动作明确声明类型，不再依靠渲染层动作名正则决定控件。

新导出保留 `recordType`，并输出可被旧版忽略或读取的兼容 `metric`。旧备份、旧模板、旧草稿和 Strong/Hevy CSV 继续可导入；缺少 `recordType` 时在规范化阶段迁移，不改写源文件。正式记录仍复用 `weight` 与 `reps` 数值槽位以降低迁移风险，其中时长保存在 `reps`，`completion_only` 两者均为空。

## 4. 休息过渡与误触恢复

完成一组后进入休息锁定态。休息卡显示已完成组、下一组动作、目标、倒计时、暂停/继续、`+30 秒`、跳过休息和“立即开始下一组”。当前组区域只显示只读预览，不渲染实际输入和“完成这组”。完整计划的折叠入口始终可用。

点击“立即开始下一组”、跳过休息或计时自然归零后，清除休息锁定并激活下一组输入。刷新后从草稿恢复时按绝对结束时间继续；已过期的休息在恢复时直接进入可输入状态。休息卡与当前组不会同时出现两个主按钮。

完成和跳过操作由模型保证幂等，最近一次完成或跳过均可通过显眼的撤销操作恢复为待完成。结束、提前结束和放弃仍使用现有确认流程，不增加独立页面。

## 5. 手机行为

在 320、375、390、430 px 验证：

- 主要触控目标和关键次要操作最小高度 44 px；
- 页面无横向滚动；
- 数字输入获得焦点时滚动到可见区域，并给训练区保留移动端安全间距；
- 休息锁定态只保留“立即开始下一组”一个主操作；
- 完成或跳过后撤销入口保持可见，重复点击不会重复推进状态；
- 完整计划可查看，但不改变休息锁定。

## 6. 本地 Beta 事件模型

新增独立纯模型 `public/local-beta-funnel-model.js`。模型只接收存储适配器、应用版本、算法版本和时间/ID 工厂；存储异常全部捕获并返回空结果，不阻断训练。

事件白名单字段：

- `installationId`：首次使用时生成的匿名本机 UUID；
- `name`：允许的事件名；
- `timestamp`：ISO 时间；
- `appVersion`；
- `algorithmVersion`；
- `templateId` 或 routine ID；
- `environment` 枚举；
- `goal` 枚举。

不得保存备注、动作重量、次数、时长、RPE、疼痛原文、邮箱、Cookie、身份令牌或自由文本。事件上限为 1000 条，追加时删除最旧记录。内部去重元数据与导出事件分开保存，只包含随机会话/计划键和已发事件名。

事件定义：

- `onboarding_completed`：首次配置成功保存；
- `workout_started`：每次创建新的训练会话；
- `first_set_completed`：每个会话首次完成组；
- `workout_completed`：正式训练记录保存成功；
- `next_plan_generated`：保存训练后生成下一计划；
- `next_plan_modified`：用户修改动作、日期或恢复选择；
- `next_plan_accepted`：确认下一计划；
- `returned_workout_started`：已有至少一次完成训练后再次创建训练会话；
- `workout_abandoned`：用户明确放弃草稿，或创建新会话替换仍未完成的旧会话；
- `recommendation_feedback`：提交推荐反馈。

不使用“关闭页面超过若干分钟”之类推断来记录放弃。去重键阻止同一业务动作因双击、重复渲染或刷新重复记事件；不同训练会话仍可产生各自事件。

## 7. 查看、清除、导出与汇总

在现有帮助/数据管理区域增加一个折叠的“本地 Beta 记录”区，不新增导航或分析卡片。它显示本机记录数量、最近事件的非敏感字段和明确的“仅保存在此浏览器”说明，并提供：

- 单独导出 `what-to-drill-local-beta-YYYY-MM-DD.json`；
- 清除事件及去重元数据；
- 不改变训练记录、设置、账号或云备份。

导出文件包含 schema 版本、导出时间、事件数组和开发/测试汇总。`summarize(events)` 输出：首训启动、首训完成、下一计划接受、第二次训练启动、第二次训练完成和推荐反馈分布。单机汇总步骤值为 `0/1`，推荐反馈按允许的枚举值计数，便于封闭测试后离线合并。

## 8. 隐私、版本与离线缓存

更新应用内说明、`privacy.html` 和 README，明确本地漏斗不等于在线分析，不上传健康内容，不随云备份同步，可查看、清除和单独导出。Service Worker 缓存加入新模型文件并提升缓存版本；`package.json` 提升补丁版本，所有发布元数据保持一致。

## 9. 测试与验收

纯模型测试覆盖：

- 六种动作类型及旧 `metric`、旧自定义动作和旧草稿迁移；
- 类型对应的正式记录值；
- 休息暂停、继续、延长、跳过、过期恢复和锁定状态；
- 事件字段白名单、去重、1000 条容量、清除、存储失败静默降级和汇总；
- 第二次训练启动/完成判定。

浏览器 smoke 覆盖首次 radio 的真实默认、键盘切换、无障碍选中状态和刷新恢复；休息态预览与激活；动作类型控件；漏斗查看/导出/清除；320 与 390 px 的 44 px 触控目标、输入可见、无横向滚动和撤销能力。完整 `npm.cmd run test:smoke` 必须连续通过两次，并提供 320/390 px 截图及手机手工测试步骤。

提交后推送当前分支，等待 GitHub Pages workflow 成功，再用公开 `/`、`/app/` 和隐私页验证版本、资源加载、关键交互和控制台错误。

## 10. 后续单边界抽取

仅在上述主验收全部完成后，另开独立任务从 `app.js` 抽取训练会话控制器；一次只抽训练会话边界，不同时处理云同步控制器，不重写框架。抽取前后必须保持相同行为并用既有训练会话与 smoke 测试验证。
