# WhatToDrill 训练推荐黄金场景设计

日期：2026-07-27

## 目标

用数据驱动的黄金场景证明现有推荐在环境、目标、恢复和历史变化下稳定、合理、可解释；测试发现不正确行为时修复实现，不把缺陷固化为预期。

## 方案选择

采用“扩展现有纯轮换模型”方案。`training-rotation-model.js` 已负责环境归一化、目标处方、轮换和历史查询；新增单一推荐决策入口比继续在 `app.js` 堆分支或引入第二个重叠模型更小、更可审计。DOM、localStorage、导入导出和 ID/时间戳仍留在应用层。

## 决策接口

纯模型入口接收模板、轮换、目标、环境、明确器械、训练历史、恢复摘要、计划日期约束和可选指定训练日，返回处方后的训练内容及：

- `selectedTemplateId`
- `routineTransition`
- `environmentConstraint`
- `goalPrescription`
- `recoveryAdjustment`
- `progressionSource`
- `scheduledDateReason`
- `safetyOverride`
- `algorithmVersion`

用户可见理由只由这些决策值映射生成。决策结果不保存睡眠、精力、酸痛、疼痛的原始副本，只保存采用了哪条恢复或安全规则。

## 规则顺序

1. 归一化旧环境 `home`，根据明确拥有的器械选择 A/B 模板并校验器械子集。
2. 从当前轮换位置选择训练日；恢复覆盖只替换本次内容，不推进或永久修改 routine。
3. 应用目标处方，使健康入门、增肌、力量在组数、次数、RPE 或推进策略上有真实差异。
4. 对每个动作优先取最近一次同名动作的真实记录；训练日完成结果只决定是否允许推进。
5. 未达标时维持负荷；连续两次未达标时保守降量；轻松达标时才按目标小幅推进。
6. 睡眠差、精力低或酸痛高只临时降量；明显疼痛改为非诊断性的恢复计划。
7. 计算计划日期理由并从结构化决策生成用户理由。
8. 结果必须引用存在的模板、包含非空且 ID 唯一的动作，并保持已手动修改的下一计划不被普通渲染重建。

## 测试矩阵

采用 pairwise 场景覆盖 5 类环境、5 类目标、4 类状态和 9 类历史；关键完整链路单独覆盖 A 后 B、B 后 A、A 后恢复再 B、连续两次未达标、漏过计划日期、较早同动作数据优先、手动计划保留。每个场景声明覆盖的规则 ID，测试汇总场景数与规则覆盖。

## 兼容与迁移

下一计划仍使用版本 2，新增可选 `decision` 字段；旧 localStorage 和旧 JSON 缺少该字段时按原字段正常化，不回填健康原始数据。Strong/Hevy 导入与历史训练结构不变。普通渲染不生成新计划，只有保存训练、明确修改推荐条件或用户动作才重算。

## 边界

不实现高级周期化、专项竞技编排、伤病诊断、康复处方、动作替代医学判断、1RM 测试或精确热量消耗估算。明显或持续疼痛仅提示停止高负荷并咨询专业人士。
